# 3CT 每日自动化升级

本项目从本机 **3CT 1.2.5** 的 Electron 资源与 sourcemap 恢复业务源码，复用原有 `window.ctAPI`，生成独立桌面副本。原始程序目录保持不变。

## 交付入口

**本机已生成可运行副本。** 先退出原版（包括托盘），双击根目录的 [start-3ct-auto.cmd](/D:/1111/2class/start-3ct-auto.cmd)，在右下角 AutoPanel 选择模块、账号、校区和参数。先点“立即预览”，确认计划后取消“预览”并开启右上角开关；以后重开升级版会恢复上次启用状态。

需要从源码重新构建时使用：

```powershell
python desktop/install.py build
```

生成后先完全退出原版 3CT（包括托盘），再运行升级版。原版与升级版沿用同一用户资料与单实例锁，不可同时运行。**本项目不关闭用户正在运行的原程序。**

## 自动化的目标流程

- 校园跑：首次选择账号、校区、距离、时长和每日时间，此后到点调用原程序上报能力，无需每天点击。
- 俱乐部：按关键词筛选当天活动，在每日报名上限内自动报名，再于活动时间窗内签到、签退。
- 二课：按关键词报名并持续关注已报名活动；在签到/签退窗口开始后延迟检查本活动绑定图库，解码对应阶段的有效二维码，再提交。
- 二维码默认采用「延迟 2 分钟、重试间隔 2 分钟、最多 3 次」，不每次调度都查询图库，不越过官方截止时间。

首次默认关闭且为预览模式。用户应先配置并预览，再明确开启真实执行。电脑必须保持唤醒、应用保持运行；睡眠、关机、程序完全退出时不会执行，不宣称后台云运行。

## 已知边界

- 有效二维码依赖上传者，缺图、无法解码、阶段不能确认或跨域图片不可读时不能保证签到成功。
- 二课拍照、定位＋拍照及验证码签到未必具备自动提交所需材料，不应把“需人工”显示为已完成。
- 上游服务可能改变字段、时间窗、登录要求或风控；离线测试通过不等同于真实平台已接受操作。
- 提交结果未知时停止自动重投，需先在原平台核查，以防重复报名或打卡。
- 使用须符合学校和平台规定；账号由程序内部正常使用，不导出、打印密码或 token。

## 开发与验证

```powershell
python -m unittest discover -s tests -v
python -m unittest discover -s reverse -p "test_*.py" -v
node --test desktop/test-automation.cjs
```

已验证：Python 164 项、ASAR 提取 7 项、桌面引擎 51 项，以及浏览器面板 54 项；独立副本已在临时资料下启动真实 Electron，确认面板与接口桥接加载。浏览器业务测试采用 fake API，没有以真实账号向学校平台提交跑步、报名、签到；不能据此承诺积分到账。具体记录见 [验收报告](/D:/1111/2class/docs/desktop-test-results.md) 与 [打包验证](/D:/1111/2class/docs/package-verification.md)。

当前二课自动签到仅支持扫码方式。拍照、定位＋拍照、验证码仍需人工；二课会话过期时也需要重新登录。

辅助 Python 调度模块提供配置校验、离线预览、持久化去重及依赖测试，不是桌面一键操作的必需入口。未配置业务适配器时，Python CLI 不能假装真实业务成功。
