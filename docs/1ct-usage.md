# 1CT 使用说明（多成员版）

> 一个程序替多人刷二课 / 校园跑 / 俱乐部；二课积分缺口自动从学校官网同步，不用手填。

## 启动

双击 [启动1CT.exe](../启动1CT.exe)（仓库根目录，**唯一的用户入口**）。无控制台窗口。`1CT\` 目录里的 `1CT.exe` 是 Electron 本体，不要直接点它。

**与 3CT 完全独立**：1CT 用自己的 `%APPDATA%\1CT` 数据目录与独立单实例锁，因此 **可以和 3CT / 3CT-Auto 同时开着**。

- 首次启动需要在 1CT 内重新登录（不继承 3CT 的登录态，这是独立化的代价）
- 想回退成共用数据目录：`启动1CT.exe --shared-user-data`，或设环境变量 `CT_SHARE_USER_DATA=1`（此时又不能与 3CT 同时运行）

## 首次配置（3 步）

### 1. 加成员

「成员」页 → 新增成员：

- **姓名 / 备注**：随便填，用于区分
- **二课**：填学号 + 密码 → 「登录并保存会话」。登录成功后，密码保存在本机成员数据里，用于会话过期时自动重登；界面显示掩码，日志与导出**不含**凭证。
  - 备用：也可以粘贴已有的二课会话 JSON（`ct_ek_session_v1` 结构）
- **校园跑 / 俱乐部**：填手机号 + 密码（两个模块共用同一套 tanma 账号）→ 「校验账号」
- **八模块缺口**：**不用填**。保存后用下面的「同步官方成绩」拉取

### 2. 同步官方成绩

有三种触发方式：

| 位置 | 操作 |
|---|---|
| 成员弹层 | 「同步官方成绩」按钮（单个成员） |
| 二课页顶部 | 「同步全部成员成绩」（批量，默认 6 小时内不重复打） |
| 运行页 | 开关「启动时自动同步成绩」（默认开，每轮运行前对 >6 小时未同步且有会话的成员自动拉取） |

同步结果同时写入两处：成员档案的 `ekModules` 与引擎的积分快照，所以**策略决策与统计展示用的是同一份数**。

口径：官方 `CurriculumName` 与 8 个模块名精确匹配；`Info` 的 `AGetNum..HGetNum` 做交叉校验，不一致则整份标记不可信、不落盘；上游缺某模块时记 `null` 而**不当 0**。

### 3. 开模块 + 关预览

运行页勾选三大模块，配置参数（关键词、每日上限、执行时间等），**先开预览跑一轮确认计划**，再关掉预览正式运行。

## 多成员怎么工作

- 每个成员独立存储：`1ct:state:<id>`（去重状态）、`1ct:config:<id>`（覆盖配置）、`1ct:scores:<id>`（积分快照）
- 一轮运行会**串行**跑所有启用成员；某个成员报错不影响其他人（记 `member-error` 继续下一个）
- 二课会话过期时自动：`refresh_token` 续期 → 失败则用学号密码重登 → 再失败才跳过该成员二课模块（校园跑/俱乐部继续）
- 全局「预览模式」只存在全局层，成员级 config 不能覆盖它

## 二课签到如何工作

1. 优先用「有图库」里志愿者上传的二维码（本地 jsQR 解码后提交）
2. **没有任何可用二维码时**（冷门活动常见），走官方 `StuSaveSignIn` 无码直签兜底：`SignWay=1` + 空照片/定位，经实测服务端会正常落库
3. 仍然只对 `SignWay=1`（扫码）活动生效；拍照/定位/验证码活动会标记 `need-manual-sign-way` 等待人工
4. 保留开关 `ek.noQrFallback=false` 可关闭兜底，回到"只认二维码"的旧行为

## 窗口操作（无边框窗口，按钮在右上角）

| 按钮 | 作用 |
|---|---|
| —（最小化） | 最小化到任务栏 |
| □（最大化 / 还原） | 切换最大化（双击顶栏空白处同效） |
| ×（退至后台） | **最小化到托盘继续运行，不会退出**。首次点击会把关闭行为固定为「托盘」，之后点 × 不再弹询问框 |

真正退出：右键托盘图标 →「退出 1CT」。顶栏空白处可拖动窗口。

## 校园跑：窗口与里程都是自动随机，不用手填

| 参数 | 行为 |
|---|---|
| 有效窗口 | 每天从 **39~48 分钟** 随机取一个；**当天固定**（跨天重随机）。用于判断「今天还能不能执行」 |
| 里程 | 每天从 **1000~1099 米** 随机取一个，且**末位一定不是 0**（1000/1100 这类整数会被上游判为异常直接作废） |
| 时长 | 仍可配置（默认 30 分钟） |

两者都会持久化到当天状态，重启程序也不会变；当天成功后按去重不再重复提交。

## 二课已报名列表

「二课」页底部有「已报名的二课」卡片：

- 数据 = **官方已报名列表**（`activityStatus=1`，自动翻页拉全）∪ **本地执行历史**（报名成功的事件）；**以官方接口为准**，本地历史只做补充
- 所以换电脑 / 覆盖更新 / 清空本地状态后，官方已报名的活动照样显示，**不再清零**
- 列：活动 / 类别 / 报名时间 / 签到状态 / 签退状态
- 签到/签退状态数据源优先级：**官方报名列表 `GetStuAllActApplyList`（与官网「报名/完成列表」页同源，字段 `SignD`/`SignT`/`Inputdate`/`SignOutdate`，一次批量拉 4 页左右）> 官方签到记录 `GetStuActSignList` > 本机执行记录 > 官方详情兜底**；官方行昨天已签到/已签退会正确显示「已签到/已签退」（悬浮提示注明「来自官方报名列表」等来源）
- 官方报名列表/签到记录/详情状态按成员缓存 5 分钟（有效期内直接渲染、不重复请求）；读取中/失败数会显示在卡片说明里，点「刷新」强制重拉
- 每行活动名下方显示**官方签到时段 / 签退时段**（来自活动详情 `ActivityQDDate`/`ActivityQTDate`，例：`签到时段：2026-10-17 19:00至2026-10-17 21:30 · 签退时段：2026-10-17 19:00至2026-10-17 21:40`），方便同学提前安排哪些时间段需要开电脑挂程序；活动无需签到/签退时显示「无需签到/无需签退」，取不到显示「—」
- 「最近活动」表 = **官网报名列表里最近签到/签退成功的 6 个活动**（按官方 `Inputdate`/`SignOutdate` 倒序；官网不可用时回退本机记录，并在表下提示来源）
- 二课会话过期时，打开二课页或点刷新会**自动尝试续期**（refresh token），失败再用保存的学号密码重登一次；成功后卡片说明显示「已自动重新登录二课」，仍失败才提示去成员页重新登录
- 只有所有来源都取不到状态时才显示 **「—」**，不会谎报「未签到/未签退」
- **引擎对官网已报名活动无条件跟踪签到/签退**，不需要关键词命中，也不受本机历史缺失影响
- 官方接口读取失败时降级为「官方列表读取失败，以下为本地记录」，不会清空已有数据
- 右上「刷新」按钮可手动重拉

## 统计与导出

- 「二课」页：签到/签退成功数、最近活动表、八模块进度条（达标绿 / 未达标黑 / 未填灰）、缺口合计
- 来源徽标：`官方成绩`（从学校接口同步）或 `手工`
- 「导出 CSV」：两段表（模块表 + 活动明细表），自带 UTF-8 BOM，Excel 直接打开不乱码
- 统计窗口：最近 90 天；成功 = 上游 `errcode=0` 且响应不含「无法/无需」；提交成功 ≠ 官方积分到账

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 二课徽标显示「需重新登录」 | 会话过期 → 点「同步官方成绩」或重新「登录并保存会话」 |
| 更新后「已报名」清零 / 报名了不签到 / 官网已签到但 1CT 显示「—」 | **已修复**：已报名列表直连官网（`activityStatus=1`，自动分页），引擎对官网已报名活动无条件跟踪签到/签退。签到/签退状态优先取「官方报名列表（`GetStuAllActApplyList`，`SignD`/`SignT`，与官网报名/完成列表同源）」，其次官方签到记录、本机记录、官方详情兜底；会话过期会自动重登一次。所有来源都取不到才显示「—」 |
| 积分缺口显示 `—` | 还没同步过官方成绩，或该成员二课未登录 |
| 统计页与列表数字不一致 | 正常应一致；若不一致，重新同步一次官方成绩 |
| 「同步失败：官方接口返回为空」 | 学校接口返回了空 TypeList，稍后重试；旧值不会被清空 |
| 运行了但没签上 | 看「日志」页的 reason：`before-window`（没到时间）/`not-applied`（没报名）/`need-manual-sign-way`（非扫码活动） |
| 电脑关机期间的活动 | 应用内调度只在程序运行时生效，关机不补跑 |

## 二课签到方式支持矩阵（当前）

| 活动签到方式 | 是否自动 | 做法 |
|---|---|---|
| 扫码签到 | ✅ | 图库有二维码 → 提交真码；没码 → 无码直签兜底 |
| 拍照签到 | ✅ | `StuSaveSignIn` + 图库照片（官方 UpFilePath 上传） |
| 定位+拍照签到 | ✅ | 同上 + 活动详情里的中心坐标（误差 0 米） |
| 签到码（现场验证码） | ⏸ **不报名** | 没有可取来源，遇到这类活动直接跳过，不占名额 |

图库没有可用照片时，用**内置兜底照片**（`dist/renderer/1ct/fallback-photo.js`，内联 data URL）代替 —— 照片不做人工复核，冷门活动也能签上。

## 关于 3CT 社区图库（不接）

3CT 逆向过来的 `activityBoundImages` IPC 还在，但它请求的是 **3CT 自己的后端**
（`api.3ct.f.can6.top/api/ek/activities/<活动>/images/`），实测**无 token 直接 401**。
要用就得登录 3CT 账号——而它对签到没有增益：

- 扫码签到：无码直签已经能过，不需要别人上传的二维码
- 拍照 / 定位签到：内置兜底照片已经够用（照片不做人工复核）
- 签到码活动：本来就不报名

所以 1CT **不接 3CT 登录**，也不默认请求那个后端（`ek.backendGallery=false`），
避免多余的第三方请求和存一个 3CT 密码的风险。
如果哪天想恢复社区图库，把 `ek.backendGallery` 打开并补一个登录入口即可，引擎侧已支持。

## 记录页

「记录」tab 汇总俱乐部（报名 / 签到 / 签退成功数 + 明细）与校园跑（成功次数 + 里程/时长明细），数据与二课统计同源（本机执行历史），可按成员筛选。

## 校园跑随机参数（全部无需手填）

| 参数 | 规则 |
|---|---|
| 有效窗口 | 每天 39–48 分钟随机，当天固定 |
| 里程 | 每天 1000–1099 米随机，末位非 0（避开 1000/1100 被判异常） |
| 时长 | 每天 31–39 分钟随机，**不含 5 的倍数**（避开 30/35/40） |
