# 二课报名排错指南（AutoPanel 日志）

> 本指南说明「3CT 自动版」AutoPanel 中二课报名决策日志的阅读方法，用于定位
> “为什么没有报名/为什么没签到”。日志只做本地展示：**不触发真实请求、不读取用户
> 凭证、不包含 token/密码/完整手机号**。本文件不包含任何真实用户日志或账号信息。

## 1. 在哪里看

打开 3CT 自动版 → AutoPanel →「日志」标签页。每轮扫描/提交会输出：

```
二课报名｜活动名称｜决策｜原因(代码)
二课扫描：抓取 N / 可报名 N / 已报 N / 待确认 N / 过滤 N / 截断 否
本轮：成功 N / 失败 N / 未知 N / 等待 N / 预览 N / 跳过 N
```

- 行首是“模块+动作”：`二课报名`、`二课签到`、`二课签退`、`俱乐部报名/签到/签退`、`校园跑`。
- `活动名称`为官方活动标题（安全文本，最多 40 字）；标题缺失时显示 `活动#xxxxxxxx`（内部 id 前 8 位）。
- `决策`是给人看的中文结论；`原因(代码)`保留原始 reason code，便于对照本表排错。
- 第二轮起的 `二课扫描` 汇总来自 engine 的 `result.ekScan`（见 §4）；engine 尚未升级时
  相关字段可能显示「—」（表示“未知”），**不会把缺失数据当成 0**。

## 2. 决策中文含义（最重要）

| 日志显示 | 含义 | 是否已发请求 |
|---|---|---|
| 可报名（待提交） | 列表状态允许报名，但还要通过积分策略/时间窗/每日上限检查 | 否 |
| 报名成功 | 上游已接受本次报名提交（**不等于官方已入账加分**） | 是 |
| 已报名 | 列表/详情显示此前已报名；不会重复报名 | 否 |
| 已报名（冲突按已报名） | 同活动在“可报名/已报名”两次查询中冲突，按已报名处理，绝不重复报名 | 否 |
| 模块已达标 | 该活动所属二课模块已满足要求，停止新增报名 | 否 |
| 积分阻断 | 积分策略阻断（原因见括号里的 score-* 代码） | 否 |
| 类别待确认 | 活动类别无法映射到八个官方模块，按保守策略不报名 | 否 |
| 关键词不匹配 | 活动标题不含配置的关键词且未开启“允许全部” | 否 |
| 未到报名时间 | 报名窗口未开始（`before-apply-window`） | 否 |
| 报名窗口已过 | 报名窗口已结束（`apply-window-passed`） | 否 |
| 未到签到/签退时间 | 签到/签退窗口未开始（`before-window`） | 否 |
| 签到/签退窗口已过 | 签到/签退窗口已结束（`window-passed`） | 否 |
| 达到每日上限 | 今日报名数达到 dailyLimit | 否 |
| 预览（不提交） | 当前是预览模式，只做判断不写平台 | 否 |
| 等待材料 | 缺二维码/定位/签到方式等，等待下一轮 | 否 |
| 失败 / 结果未知 | 上游拒绝或提交结果无法确认；未知结果不会自动重试，请人工核查 | 是/可能 |

> 注意：`可报名（待提交）` **不等于** `报名成功`；只有 `报名成功` 才表示上游接受了提交。
> `已报名` 只是“本来就报过”，不是本轮成功。

## 3. 原因代码（reason code）中文对照

报名相关：

| code | 中文 |
|---|---|
| before-apply-window | 未到报名时间 |
| apply-window-passed | 报名窗口已过 |
| missing-apply-window | 活动缺少报名窗口信息 |
| already-applied | 已报名 |
| already-applied-conflict | 查询结果冲突，按已报名处理（不重复报名） |
| daily-limit-reached | 达到每日上限 |
| module-satisfied | 该模块积分已达标 |
| category-unknown | 活动类别无法映射 |
| need-keywords | 未配置关键词（或未开启允许全部） |
| score-snapshot-missing | 积分快照未导入 |
| score-account-mismatch | 积分快照与当前二课账号不一致 |
| score-untrusted | 积分数据不可信（缺字段/数据异常） |
| score-stale | 积分数据过期 |
| score-refresh-failed | 官方成绩刷新失败（保留旧值） |
| policy-disabled | 缺口策略已关闭（不按达标限制） |
| upstream-rejected | 上游拒绝 |
| submission-result-unknown | 提交结果未知（不自动重试） |
| apply-state-unknown | 报名状态待确认 |
| apply-disabled | 自动报名已关闭 |
| unexpected-list-shape | 活动列表结构异常 |
| scan-complete | 扫描完成 |

签到/签退相关：

| code | 中文 |
|---|---|
| before-window | 未到签到/签退时间 |
| window-passed | 签到/签退窗口已过 |
| need-sign-in-first | 需先签到 |
| need-coords | 缺少定位坐标 |
| need-sign-way / need-manual-sign-way | 缺少签到方式/需人工选择 |
| need-qr-or-manual | 需二维码或人工签到 |
| qr-retry-pending | 二维码重试等待中 |
| qr-attempts-exhausted | 二维码尝试次数用尽 |
| already-done / already-done-upstream | 今日已完成/上游显示已完成 |
| past-deadline | 已过截止时间 |
| stopped | 已停止 |
| storage-error / state-corrupt | 本地存储失败/去重状态损坏 |
| previous-result-unknown / locked-* | 上次结果未知，已锁定不重试 |

其它：`no-candidate` 未发现候选活动；`api-unavailable` 接口不可用；
`ek-not-logged-in`/`no-ek-session` 二课未登录；`no-unirun-account` 未选择校园跑账号；
`campus-not-found` 未找到校区；`preview-only` 预览模式（不提交）。

## 4. “二课扫描”汇总字段

| 字段 | 中文 | 含义 |
|---|---|---|
| fetched | 抓取 | 本轮列表接口拿到的原始活动条数（去重前） |
| eligible | 候选 | 通过关键词/模块过滤、进入候选的数量 |
| joinable | 可报名 | 列表状态允许报名（还需过积分/时间窗/日上限） |
| applied | 已报 | 已报名的数量 |
| unknown | 待确认 | 列表缺状态且详情也无可靠证据 |
| filtered | 过滤 | 被关键词/状态过滤掉的数量 |
| nextpages | 页数 | 实际翻页次数 |
| truncated | 截断 | 是否因页数上限提前停止（是/否） |

- 字段缺失时显示「—」，**不当成 0**，也不会显示 engine 不提供的字段（如“积分阻断数”“窗口等待数”）。
- `joinable` 只是“列表允许报名”，不等于已提交成功；请结合每行的“原因”判断。
- 页数被截断（截断 是）时，可能还有更靠后的活动未被扫描，可调大页数上限后重试。

## 5. 常见问题排查顺序

1. **没有“二课扫描”行**：engine 尚未升级（旧版本）→ 只看行日志；或本轮未启用二课/未登录。
2. **扫描 抓取>0、候选=0**：关键词不匹配或未开启“允许全部”（看 `need-keywords`）。
3. **候选>0、可报名=0**：检查每行原因——多为 `category-unknown`（类别无法映射）或
   `模块已达标` / 积分阻断（score-*）/ 未到报名时间（before-apply-window）。
4. **可报名>0 但没有“报名成功”**：
   - 预览模式（`preview-only`）→ 关闭预览开关并确认；
   - 积分策略阻断（`score-snapshot-missing`/`score-account-mismatch`/`score-untrusted`/`score-stale`）
     → 到「二课补分」页刷新官方成绩或导入截图初值，确认绑定当前二课账号；
   - 每日上限（`daily-limit-reached`）→ 次日或调大上限；
   - 报名窗口（`before-apply-window`）→ 等到窗口开始后自动再试。
5. **“已报名”仍未签到/签退**：报名成功只代表报名；签到/签退要看 `before-window`（未到）
   和 `need-*`（缺材料）。两类“未到时间”不会混：报名看 `before-apply-window`，签到/签退看 `before-window`。
6. **状态未知/提交结果未知**：程序不会自动重复提交（防止双报），请人工到官方渠道确认后再决定是否重试。

## 6. 隐私与边界

- 日志不含 token、cookie、密码、完整手机号；活动名为官方标题安全文本，内部 id 仅显示前 8 位。
- 本指南为通用排错说明，不包含任何真实用户日志/账号/学号；如需反馈问题，请自行脱敏。
- 日志只反映本地判断与上游响应，**提交成功 ≠ 官方已入账加分**；积分以官方成绩快照为准。
- 不触发真实业务请求；仅在用户主动运行自动化时由 engine 执行，且预览模式默认不提交。
