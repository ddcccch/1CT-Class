# 二课积分策略分析与自动化看板使用指南

> 本文面向使用者，说明「3CT 自动版」的积分缺口策略、自动化看板用法，以及数据口径与边界。
> 看板新增的数据（积分快照/执行历史）只保存在本机 localStorage，不上传；原 3CT 自身的正常业务请求（登录、成绩查询等）仍会按原程序行为发往其官方服务。看板不持久化原请求凭证（token/cookie），也不保存账号密码。

## 1. 官方八模块与截图初值

3CT 源码里的二课积分要求（`EK_SCORE_NEED`）与一张用户提供的匿名截图初值如下（**截图初值不是实时成绩**，仅作演示/起步参考）：

| 模块 | 要求 need | 截图初值 got | 分类缺口 max(0,need-got) | 状态 |
|---|---|---|---|---|
| 艺术体验与审美修养 | 12 | 2 | **10** | 缺 |
| 思想政治与道德修养 | 12 | 6 | **6** | 缺 |
| 社会工作与能力拓展 | 8 | 3.5 | **4.5** | 缺 |
| 学术科技与创新创业 | 8 | 4 | **4** | 缺 |
| 人际交往与沟通能力 | 8 | 4 | **4** | 缺 |
| 社会实践与志愿服务 | 12 | 11 | **1** | 接近达标（可快速补齐） |
| 传统文化与人文素养 | 8 | 8.5 | 0 | **已达标** |
| 心理素质与身体素质 | 12 | 15.5 | 0 | **已达标** |

- 合计要求 **80** 分，截图初值合计 54.5 分，两个口径不同，别混用：
  - **官方总分口径**：80 − 54.5 = **25.5 分**（总分差）；
  - **分类缺口口径**（看板展示、策略使用）：逐模块 `max(0, required − current)` 求和 = 6+4+10+0+4+0+1+4.5 = **29.5 分**，共 **6 项缺口、2 项达标**。
  - 分类缺口不会因为某模块超额（15.5/12）而抵消其他模块的缺口，所以 29.5 > 25.5。
- **补分优先级建议**（缺口大 → 小）：艺术(10) → 思想(6) → 社会工作(4.5) → 学术(4) / 人际(4) → 志愿(1，接近达标可快速补齐)。
  > 注意：这只是优先级建议，**自动策略只按活动真实 category 的缺口判断**，不会根据活动标题/拼音猜测类别；类别无法识别时一律 fail-closed（不自动报名）。

## 2. 缺口策略如何工作（默认启用）

- `config.ek.scorePolicy.enabled` 默认 **true**：
  - **未导入/未刷新成绩前**：缺口未知 → 策略暂停**新增报名**（不把未知当 0，也不假装达标）；已报名活动仍继续签到/签退。
  - 成绩可信且新鲜时：**已达标模块停止新增报名**；已报名活动继续按官方窗口完成签到/签退（防止违约）。
  - 未达标模块：允许按关键词/类别新增报名（受每日上限约束）。
- 成绩过期（stale）时：保留旧值展示并提示“可能过期”；**策略按 fail-closed 处理**——stale/不可信时暂停新增报名，已报名活动继续签到/签退。
- 关闭策略：可在配置中设为 false（不推荐；会取消达标限制与 unknown 暂停）。

## 3. 成绩来源与刷新

看板「二课补分」页支持两种来源，来源会显示在概览卡片上：

| 来源 | 显示 | 是否实时 |
|---|---|---|
| 官方成绩（`ctAPI.ek.getStudentScores`） | 官方成绩 | 是（刷新时） |
| 截图初值 / 手工编辑 | 手工数据（非实时） | 否（仅本机参考） |

- **刷新分数**：点看板右上角「刷新分数」；内部每小时最多自动一次，点击按钮可强制刷新。刷新失败会保留旧值并提示原因。
- **使用截图初值**：点「使用截图初值」→ 确认框 → 绑定**当前二课账号**并保存（非实时）。未登录二课会提示先登录。
- **手工编辑**：可修改各模块「要求/已得」，要求必须是 >0 的有限数字，已得留空=未知（不按 0 保存）；保存需确认，且只写入本机当前账号。
- 绑定行为：导入会绑定**当前 ek 登录账号**；若引擎返回账号不一致会拒绝覆盖（不静默重绑）。

## 4. 执行结果统计口径（看板「概览 / 执行记录」）

- **成功 = 上游已接受该动作**（接口返回成功），**不等于官方入账**；看板**不会**因此自动增加积分。
- 待定/预计分不计入到账；未知结果不自动重试、不重复提交。
- **“签到＋签退完成”**（看板卡片名，不泛称“全部活动完成”）：同一活动（同一模块+账号+活动+日期）必须**签到(in) 和 签退(out) 两端都成功**才计 1 次；只有报名或只有签到不算。官方“无需签退”的活动目前没有 official flag，暂不判为完整（后续官方标记再支撑），因此该数字偏保守，看到 0 不代表没签到。
- **逐模块/逐动作成功数**（概览卡片，均按“上游已接受动作”计数，非到账）：
  - 校园跑成功次数（官方实际 action `unirun.autoRun`，看板兼容展示键 `unirun.run`）；
  - 俱乐部报名 / 签到 / 签退（`club.join` / `club.signIn` / `club.signOut`）；
  - 二课报名 / 签到 / 签退（官方实际 action：`ek.apply` / `ek.signIn` / `ek.signOut`；看板卡片兼容展示键 `ek.join`，两者计数等价）。
- **校园跑距离**：仅 unirun 成功且已确认 runDistance 时累计展示。
- 俱乐部：报名 / 签到 / 签退分别记录，不混算。
- 预览（dry-run）轮次**不计入**历史，也不计成功。
- 历史有界：最多 2000 条、最多保留 90 天（先到上限先淘汰），统计只看窗口内数据。

## 5. 账号隔离

- 二课使用 ek 账号；校园跑/俱乐部使用 tanma 账号（`unirunAccounts` 中选定项）。两套 ID 不同。
- 「执行记录」默认只显示**当前账号组**（ek + 当前 tanma）的记录，可在账号下拉切换「全部账号」或单个账号；这样不会因为混用两套 ID 而出现空列表。
- 界面账号一律掩码显示（如 `138****1234`）；历史存储中手机号类账号会做哈希化处理，避免同一头尾号冲突，也不存完整手机号。

## 6. 打开看板

- 打开 3CT 自动版后，在 AutoPanel 点 **「结果看板」** 按钮（`data-testid=a3-open-dashboard`），打开全屏看板。
- 三个标签页：
  - **概览**：总缺口（已知/未知分开显示）、已达标 N/8、缺口策略状态、二课/校园跑账号、分数来源与更新时间、stale 标记、八模块进度条、执行成功趋势（7/14 天）、执行结果摘要（含校园跑距离）。
  - **二课补分**：刷新/截图初值/手工编辑 8 模块，保存前确认。
  - **执行记录**：按日期/模块/状态/账号筛选，明细表 + 脱敏 JSON 导出（仅本地）。
- 空状态显示「尚无记录」，不会伪造成功数据；数据缺失显示「未知/待导入」，不会显示 0 缺口或“全部达标”。

## 7. 隐私与排错

- 不持久化原请求凭证（token/cookie/密码）。
- 不把截图/用户信息里的姓名、学号额外复制进代码、测试或文档；积分快照按**当前登录账号 ID**（ek loginName，可能是学号）在本地隔离保存，界面一律掩码显示（如 `20***01`）。
- 历史存储中的手机号类账号会哈希化，避免同头尾号冲突；看板导出为脱敏 JSON。
- 本地存储键：`auto3ct:scores`（积分快照，按账号隔离）、`auto3ct:results`（执行历史，脱敏）。
- 若看板提示「执行历史保存失败」：检查磁盘空间/权限；本地存储损坏时看板会停止写入以保护原数据，可先导出后重置（在「执行记录」页操作）。
- 若「使用截图初值」按钮不可点：通常是没有加载到最新 `dashboard.js` 或未登录二课；看板会提示原因。
- 本功能不访问任何第三方网络接口（除 3CT 自身已有的官方成绩查询外），不需要外网依赖。
