## 策略边界

- 截图数据是用户提供的初始参考，不是实时官方分数；用户明确导入后才绑定当前二课账号。
- 官方成绩来自既有 `ctAPI.ek.getStudentScores` 的 `TypeList.CurriculumName/SumScore`。缺模块、非法数字、账号显式不匹配不能当作 0 或覆盖可信数据。
- 活动归类来自详情 `ModuleCodeText` 或官方 `ModuleCodeList` 的 code/label 映射，不能凭标题猜类别。
- 默认启用补缺策略：成绩缺失、不可信、过期或账号不匹配时阻止**新增报名**，显示原因。
- 已报名活动保持跟踪签到、签退，不因为后来足额而自动违约。若用户不再参加，应由用户确认是否取消或关闭对应自动化。
- 报名、签到、签退提交成功不能作为积分增加依据；只有刷新官方成绩或用户明确录入的成绩可以改变分数快照。

## 结果看板口径

- 成功动作与完成活动分开统计，签到和签退不能算两次完整活动。
- 校园跑里程仅在已知距离且上游明确成功时累计；缺历史参数时显示未知，不编造公里数。
- 校园跑、俱乐部和二课账号是不同身份空间，筛选与历史需按模块/账号隔离。
- preview 不计真实成功、不污染真实历史、QR 次数与官方成绩缓存。
- `onResult` 与每轮结果可能报告同一 key，需幂等合并，后续 already-done/skip 不能覆盖真实 success。
- 等待/失败/未知应保留可见原因；历史有容量和保留期限，界面说明统计范围。
- 看板活动名用安全文本渲染；不存 token、密码、原始业务 payload 或完整手机号。

## 验证层次

1. 纯函数：截图缺口29.5、边界恰好达标、未知模块、非法成绩、官方数据解析。
2. 引擎：达标阻报名、未达标允许、刷新后停止、账号切换、已报名继续跟踪、preview 无副作用。
3. 历史：真实结果幂等、重启保持、账号日期筛选、成功不被skip覆盖、无假到账。
4. 浏览器：点击导入与官方刷新、打开全屏看板、进度条与趋势、空数据和错误状态、中文布局。
5. 打包：新资源加载顺序、原包不变、新包字节对拍、最终包浏览器验收、无控制台入口保留。

- 已独立运行 Node 组合套件：积分策略30、原引擎51、积分引擎32、结果仓库31，共144项全部通过。

- 最终副本的资源字节、完整性与浏览器打包模式以最终打包验收报告的实际哈希和结果为准；真实学校平台业务未作为测试提交。
